# 字幕、口型与真实时间轴

核心：冻结实际配音，建立一个主音频时钟；声音、数字人片段、字幕和动态揭示分别映射到它。已生成SRT不代表画面真的显示字幕，文件帧率正常也不代表嘴型匹配。

## 字幕怎样制作

1. 保存认可音频哈希、实际转写/词时间和语义句段。供应商时间戳须对应本次音频；没有可信时间戳则使用本地声学对齐，检查专名、数字、末句和转写差异。不均分字数。
2. 先确定语言与顺序。双语的翻译行与原语言是同一个cue，时间完全相同；上中下英只是一个用户选项，不改语音。翻译保留含义，不能为排版删掉关键限定。
3. 字幕和SRT从同一份cue生成。按完整词/语义断行，允许经过检查的换行；禁止自动把英文长词或一个中文孤字拆到下一行。过长时重新合理分句并保留真实词边界，不能压到看不清或加速声音。
4. 用许可字体文件真实嵌入。可选择适合品牌的中文无衬线与易读拉丁字体；标题可另用展示字体。记录来源与实际字重，不仅声明一个本机字体名。MiSans/Manrope是一种已用过的搭配，不是所有品牌必选，也不随仓库自动提供它们。
5. 以1080短边为例，主字幕约40px、次字幕约31px、行高1.32/1.38、行间距约12px可作为试排起点；按实际观看尺寸、字幕长度、画幅和字体调整。最多约两帧轻淡入，不把视觉出场延迟变成语音延迟。
6. 浅底用深字，深底用浅字与适度局部阴影/底部暗带。跨明暗转场需要颜色或衬底过渡。字幕避开人物脸/手的运动范围、圆框和平台界面；中文行在上时检查英文下沿。

所有发声内容在用户要求字幕时均要覆盖。不能为了“分层展示字幕如何出现”而隐藏前两句；即便SRT包含它们也不算满足。只有用户明确要求不显示字幕的特定范围才可省略，并记录这个要求。

## 可执行字幕生成器

由Codex将实际cue转成仓库 `examples/caption-design.json` 的格式。示例中的时间是匿名测试数据，不是可用于正式片的对齐。

```sh
.venv/bin/python scripts/production_tools.py captions --plan <私人caption-plan.json> --out <新字幕目录>
```

生成 `captions.html`、`subtitles.srt`、`sample-points.json`，拒绝重复ID、时间重叠、不安全字体路径及覆盖已有目录。单语时留空secondary；顺序由primary/secondary决定。字号/底边距/左右安全区可配置。

将HTML放在工程 `compositions/captions.html`，不要和index.html并列作为第二入口。主工程加载本地GSAP，按相同composition_id挂载这个透明子合成，data-start=0、真实全片时长、显式画幅尺寸，位于图形之上。字体路径以工程根目录为基准，把许可文件放到其指向位置。生成器不安装新字体、不操作云端、不替代完整广告片设计。

## 人物口型映射

每个发声片段保留：主音频来源/哈希、源入点、最终入出点、速率、说话者；每个可见说话人物也保留这套信息。包括圆框、全屏人物，以及演示小视频里的数字人。静态材料缩略图与闭嘴听者不伪装成正在发声的角色。

映射公式：`source_time = source_start + (final_time - start) * rate`。reel中的偏移先经已保存的sample映射换回原始主音频时钟，不能把reel时间直接当全片时间。比较重叠区间的开头和末尾，同时发现固定偏移与逐渐漂移。字幕不跟图形场景的局部秒表另算一遍。

```sh
.venv/bin/python scripts/production_tools.py audit --plan <私人production-audit.json> --out <新检查报告.json>
```

格式见 `examples/production-audit.json`：

- `utterances`：实际发声的完整语义cue，含speaker及两种文字；被切开的句子先按声学边界拆成小cue。
- `captions`：实际编入工程的可见字幕，逐一用utterance_id对应；不要直接照抄预期清单假装检查过工程。
- `audio_spans`：主旁白总线的非重叠段；audio_id标识同一已认可的规范音频，source_start使用该源时间。
- `presenter_spans`：所有可见**说话数字人**的区间与同一音频来源映射；不是库存片演员的声音。全屏和圆框同时转场可以重叠，只要映射相同。
- `continuous_pip`附main_speaker时要求每个主讲cue有对应人物覆盖；selective只核对已经决定露出的部分。

检查漏句、重复/重叠、改字、声明隐藏、超过一输出帧的时移、说话者/音频源不符、reel偏移与速度漂移。它只审计**声明计划**，报告始终 `ready_for_delivery=false`；不能识别HTML被CSS藏掉、文字遮脸或人物表情自然与否，也不替你验证音频哈希的来源。这些必须做下面的实际检查。

## 最终文件检查

- 对每个实际发声cue，在可读时刻检查最终MP4的字幕文字。用可用OCR辅助；双语OCR指定对应语言，误识别需看原帧确认。没有OCR就逐句查看，不编造自动通过。关键词过渡、字幕交界、长句另检查首尾帧与连续片段。
- 所有人物区间做源时间核对，并检查实际输出开口/闭唇、换句与转场；静帧相似搜索容易把不同句的近似姿态匹配错，不能仅凭相似度认定源段落错位。
- 保持认可声音的后期修订，可以比较完整解码PCM验证音轨未偏移；重新混音时比较独立旁白stem，不能要求BGM改变后的最终混音与旧版完全相同。
- 最后完整解码、核对实际尺寸/帧率/时长、混音峰值/响度、结尾完整度、工程与输出哈希。保留检查方法和范围；抽帧、源映射、OCR与真人动态验收互相补充，不能替代。
