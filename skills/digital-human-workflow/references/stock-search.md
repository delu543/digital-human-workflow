# 按台词寻找真实视频插片

目标是动作和叙事关系吻合、人物与场景自然、裁切后仍可读。下载成功和分辨率高只是技术条件。已接受的工作中，Pexels 的原生竖屏实拍能替代突兀的大照片；这不表示所有题材或用户都应使用同一组素材。

## 检索路线与网站

| 来源 | 怎么用 | 边界 |
|---|---|---|
| [Pexels Videos](https://www.pexels.com/videos/) | 本次实际采用的实拍来源；网站筛选视频、竖向与相应动作 | 逐条看来源页与 [许可](https://www.pexels.com/license/)，避开广告推荐跳出的其他服务 |
| [Pexels API](https://www.pexels.com/api/documentation/) | 用户已有获准的 Key 时可结构化检索，保留来源页/作者/尺寸/下载格式 | 可选，没 Key 用网站，不让新人为搜索强制申请额外账号；遵守 API 署名/链接和限流规则 |
| [Mixkit](https://mixkit.co/free-stock-video/) | 主库不足时找备选短实拍；音效也可独立搜索 | 逐项确认 Free 或 Restricted 等 [许可](https://mixkit.co/license/)，本发布未验证其全自动下载 |
| 用户现有获授权素材库 | 优先复用已匹配审查过的片段 | 权利和人物/场景适配仍需记录 |
| [33 台词](https://33.agilestudio.cn/clip-search) 等电影镜头定位网站 | 搜画面/台词，帮助定位作品和时间点 | 曾实测需要登录且有个人研究学习提示；可公开观看不等于获准用于客户成片 |
| [VideoSeek](https://github.com/6v17/VideoSeek) | 大量已获授权本地视频时，作为可选语义/字幕索引候选 | 是本地检索平台，不自带电影版权；AGPL-3.0，不自动把其代码混入本 MIT 产品，未在此工作流安装验证 |

仓库不依赖以上可选检索项目启动。其他搜索代理的演示、README 或 Star 不能证明可下载、可商用、维护可靠；未核实的项目不称为已集成能力。电影片段需明确授权/适用使用依据，不能仅因为 GitHub 提供下载器就采用；缺依据时继续找可用实拍，不卡住整片其他工作。

## 具体怎么搜

1. 从台词提取可见动作：**谁与谁 / 做什么 / 什么关系 / 场所 / 情绪强度 / 必须保留的物件**。把抽象“教育焦虑”改成“家长指导伏案写字的少年”；把“恋爱关系”改成“一个人将花束交给另一个人”。
2. 优先英文动词短语，必要时补中文。按动作同义词扩展，不一次塞进十个风格形容词。
3. 优先网站 Videos 类目和原生 portrait；搜索引擎只定位页面，例如 `site:pexels.com/video/ mother helping son homework`。打开作品页再核对，不下载搜索结果缩略图。
4. 首批通常每镜头 3–5 个候选，最多两轮有方向的改词。仍没有合适的就换构图/动作代理镜头，或说明生成/采购选项及费用；不无限搜、批量下载整库。

| 需要表现的关系 | 第一轮查询 | 有方向的扩展 |
|---|---|---|
| 家长帮助孩子学习 | `parent helping teenager homework` | `mother son studying frustrated`、`father daughter homework table` |
| 家庭沟通不顺 | `parent teenager disagreement` | `family discussing homework`，优先明确沟通动作，不拿哭泣特写随意标签化 |
| 学生专注读写 | `student writing notebook classroom` | `teen studying desk close up`，检查手、笔尖与纸面接触 |
| 年轻人玩游戏 | `young gamer keyboard portrait` | `teen playing computer medium shot`，年龄/设备和画面风格符合台词 |
| 示好或追求 | `man giving flowers woman` | `couple bouquet surprise`，入点选交接动作，按文意在拥吻前结束 |
| 伴侣抱怨与倾听 | `couple disagreement conversation` | `woman talking partner listening`，不选与口播情绪完全不同的暴烈镜头 |

这些是检索语法示例，不是固定人物性别、年龄、国籍或家庭结构。以当前文案与用户要求改写。用户指定本土环境/外观时必须纳入筛选，不能默默换成其他环境。

有 API 授权时，2026-09-21 官方文档的检索入口是 `GET https://api.pexels.com/v1/videos/search`，参数包括 `query`、`orientation=portrait`、`per_page`；旧 `/videos/` 路径将弃用。读取实际响应的 `video_files` 选择可解码且足够清晰的 MP4，不拼猜测 CDN URL。密钥只用本地环境，不回显。接口升级时重新读文档，不把此日期的端点当永久协议。

## 选择与裁切要看实际动作

- 看候选的开始、中间、结束及拟采用的完整连续段。排除静帧伪视频、循环重复、AI 推荐广告、严重慢动作、过度美颜和与主片不搭的商业摆拍。
- 人物清楚自然、表演强度与台词相符、关键互动成立，比“脸好看”更可操作。不能为了美观丢掉人物关系或学习/送花的实际动作。
- 竖屏裁切后，手、笔、花束、交互双方仍须在画面内。横片若无法同时保全语义主体，换原生竖片或另设计版式；不要只默认 center crop。
- 选入出点要覆盖动作的起因/发生/短反应，而不是随机中间几秒；长度不足不冻结末帧、不循环无关动作。插片原声默认静音，以已认可旁白继续；有意保留环境声才另设混音。
- 真实素材也可能光线/肤色差异大；做有限曝光、白平衡与饱和度统一，不统一压暗，不用滤镜掩盖劣质源片。
- 普通学校/家庭素材只能作为情境，不能把校名或人物名称指向并非真实拍摄的对象。不默认加制作说明字；平台水印及实际要求的标记/署名照常保留。

每条候选记录 query、作品页、作者、许可链接与检查日期、实际文件哈希、尺寸、时长、选中源入出点、目标时间、裁切区域、选择/拒绝原因。示例结构见仓库 `examples/stock-shot.example.json`；登记到既有 `DH add-media` 后在计划引用其实际路径。下载失败先查状态、格式和官方可用路径，遇登录/限流不绕过访问限制。

## 图、图解与音效的分工

全屏生活情景优先匹配用户对实拍或生成视频的选择；动态图解中的小头像、图标、关系标志可继续用授权图像或图像生成。两者分开列在镜头清单，避免“替换照片”误删图解素材。真实数字/学校数据须来源支撑，不能让生图模型编造。

简单提示音、短过渡声可用本地合成，复杂环境声从有许可音效库找；付费 AI 音效只在现有工具不够且获预算时使用。每个音效服务一个动作/信息点，单独轨道、适度衰减，不能用持续 whoosh 或响亮提示音盖住人声。素材搜索和小图片通常可以比新增人物生成更省钱，但不把免费或低价当作质量证据。
