# 从最少输入到可交付成片

用于新用户第一次出片、长片及客户交付。用户说自然语言，Codex 负责中间计划、检索、调用、检查和恢复；不要把内部表单交给用户填写。与已有 production.md 命令配合使用。

广告片加读 [advertising.md](advertising.md)，字幕或嘴型纠正加读 [captions-sync.md](captions-sync.md)。可选素材、音乐与短版分别路由，不能将一次客户偏好变成所有用户的固定风格。

## 用户只需提供什么

创作输入：有权使用的本人照片/视频（可从清晰视频选帧）、本人声音样本或含声视频、要说的文案，以及真正影响结果的偏好。已有验收素材不重复索取。平台可能还要求单独录制同意视频，这不是创作素材可替代的步骤。

首次账号准备仍需本人处理登录/验证码、平台身份同意、密钥本地隐藏输入、订阅选择和明确预算；第一次声像短片需要本人判断相似度。Codex 尽可能合并一次说明这些必要动作。不能声称只上传照片就能跳过平台验证，或在无法试听时把自然度自动标成通过。以后同一模板和已授权范围内直接执行，不为字体、切点或工具内部状态重复提问。

优先继承用户工作区已确认偏好；否则给出简短默认方案并继续可逆准备。仅就会实质改变费用、身份、数据目的地或成片目标的缺失项询问。所谓“最高质量”落实为当前可用的适用模型与实际输出，不按模型名称、宣传或价格替用户判定效果。

## 一次制作的依赖顺序

| 阶段 | Codex 要完成的产物 | 放行依据 |
|---|---|---|
| 需求整理 | 私人需求覆盖表：口播段、必需画面、声音角色、效果、用户后续纠正 | 每条要求有编号，冲突已按最新指令解决 |
| 账户与素材审查 | 当前模型/原生分辨率/时长/水印/计费路径快照；原片检查 | 来源和权限清楚，不把缺失项伪装为完成 |
| 声像校准 | 外观约束、静态 look、动作参考、音色与模型分别记录；有限短片 | 身份相似、连续动作、眨眼、口型与声音实际认可 |
| 配音与时间轴 | 完整主讲和必要角色声音；实际声学时间、声音哈希 | 本次声音听审；不在口型完成后换音轨 |
| 出镜覆盖 | selective 或 continuous_pip；主讲/其他人/静默分段；生成片映射 | 缺口与费用在提交前算清楚，见 presenter-coverage.md |
| 分镜与素材 | 语义镜头清单、素材来源/权利、选中入出点、统一设计 | 先看素材和竖屏裁切；见 stock-search.md |
| 制作并行准备 | 同一主线下，人物生成等待时准备字幕、插片、图解和音效 | 后期不改变已确认声像、原稿或费用路径 |
| 代表段验证 | 用真实已生成素材覆盖最长字幕、全屏/圆框切换、复杂图解、换声 | 查看实际动态和手机尺度，不只看 HTML 截图 |
| 一次整片导出 | 冻结工程哈希、一次本地导出、状态和日志 | 文件存在及全解码不是全部；仍需最终画面与声音检查 |
| 交付 | MP4、SRT、一套必要素材及时间映射；编辑器工程按需 | 要求逐条闭环、最后一句完整、清晰标注实测范围 |

按依赖执行，不机械把所有步骤串行等待。这里的并行是工作顺序建议，不自动授权派生其他 Agent、云端任务或外部数据传输。

## 减少返工的时间真源

实际配音与其哈希先冻结；据此选择全部出镜范围，再核算生成reel。字幕cue、翻译行、人物片段、插片与图形事件都消费这份映射，不各自维护“看起来差不多”的秒表。换声音/语言重走同步依赖；仅改字体、圆框、BGM或背景时复用源声像。

在私人需求覆盖表标明本轮必需、可选、明确不要的项。用户说“全片都有头像”就先算连续口型成本；要求真实视频就先搜真实动作；仅需朋友圈短版就先从已认可长片选完整句。不要先大量生成，再发现布局或时长不符合。

集中收集同类问题，改共享的字幕生成/媒体映射/样式来源，先用代表段验证后再导出全片。CSS/HTML修改后检查样式确实保留、UTF-8正确、媒体ID唯一、子合成尺寸和路径真实可读；零报错但零采样不是通过。保持固定渲染依赖，不在成片返工时顺便升级整条工具链。

## 把个人要求转成每位用户的契约

不要写“所有人必须戴眼镜/穿某衣服/坐某桌前”。工作区记录 `appearance_constraints`：必须保留、允许改变、必须先确认的特征，例如配饰、发型、服装、姿态或场景。默认忠实于该用户已认可外观；对不同模型的图片/视频预览分别核对。

静态外观、动作参考、配音音色和生成模型是四个不同来源。只换高清照片不会自动改变动作参考；同一个 avatar 名称也不能证明目标引擎读取了相同 look。参考中多个服饰/姿势混在一起时选同一外观的连续段，不跨镜头拼训练段。训练/身份原片不直接进入最终口播时间线，除非用户明确改为真人混剪。

风格参考转成可执行设计语言：真实空间、克制光线、镜头信息量、图解出现顺序、口语节奏。不要为了“电影感”改变五官、过度美肤或堆叠戏剧灯光。人物表现力是第一门槛，配图和动效服务内容。

## Codex 自己完成的质量管理

- 建一份需求覆盖表，逐项连到实际音频区间、图层和验收证据；例如“有倒计时”还要检查每个数字出现时间，不能只确认文件存在。
- 新模板做一次短校准；用户认可绑定实际文件与参数。后续复用同组合，不每条重复询问身份。新完整音频仍由具备能力的 Codex 听审；工具不能听时才请用户听，不伪造证据。
- 默认不强制图片、实拍或生成视频；由内容、偏好、可得性和预算决定。要求实拍插片时，静态照片推近不算完成。
- 每次反馈先归类：源层必须重做 / 后期局部修正 / 已合格可复用。字幕、裁切、音效问题不触发新的付费声像。
- 有限候选、单变量对照、累计费用、停止条件写在私人账本。已拒绝基线不能自动复用；已通过基线也不等于长片每一秒通过。
- 停在真实门槛，不停在内部待办。`needs_*` 通常是 Codex 的下一步；平台登录、预算不足和确实无法判断的主观声像才需要用户。

## 交付与复用

直接导出 MP4，不要求安装桌面剪辑软件。素材包可为清晰目录，用户需要传输再打 ZIP；CLI 的 bundle 能力保留，不强制每次复制大包。保留已付费人物源片、已认可声音、字幕、最终选中素材、时间映射、合成源码与少量必要证据。大规模逐帧缓存与弃用候选不进入交付；删除仍按当前项目规则确认。

后续优化沉淀“症状—来源层—证据—最小修复—回归测试—适用边界”，并区分实测有效、受特定版本限制、尚未验证。只有用户要求更新产品时才提交通用规则/代码；私人素材与参数不随更新发布。
