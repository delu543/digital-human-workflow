# 长片导出、实际验收与有限恢复

默认沿用已验收的固定依赖。当前兼容适配基于 Hyperframes 0.8.48；升级是单独的兼容验证，不能在长片导出中途换版本。参考 [Hyperframes 源码](https://github.com/heygen-com/hyperframes) 与本地安装版本，不能把新版本能力强塞进旧 CLI。

## 先小后大，检查正确版本

1. 冻结声像、分镜与工程；用代表性短片验证实际渲染中的字幕、裁切、竖屏边界、圆框、一个完整转场和复杂动画。短测试要真正截断后续素材，不能只缩短根 duration 留下越界片段。
2. `check` 必须真的执行 lint/runtime/layout/motion/contrast。`0 samples` 或 `0/0 checks` 不等于通过；先消除阻止后续审计的错误。
3. 工程、检查、导出都绑定 SHA256。修改 CSS/次级图层/素材后旧检查失效；未变的声像验收与授权可复用。
4. 预检磁盘：流式编码不等于零缓存。长源片仍可能产生临时解码帧，按素材时长、帧尺寸、worker 数估算峰值，预留余量。先限制并发和持久帧缓存，不等磁盘耗尽才删除文件。

## 正常命令与后台命令

短片通常 `DH render <id>` 或 `DH edit-render <id> <revision>`。现在统一使用单 worker、low-memory、关闭持续 frames cache。长片或已证实会随聊天断开的环境，使用独立导出器：

```sh
.venv/bin/python scripts/export_project.py \
  --project /path/to/job/project \
  --output /path/to/job/exports/final.mp4 \
  --state /path/to/job/export-attempt-1 \
  --attempt 1 --max-attempts 1 --fps 25 --timeout 7200 \
  --macos-background
```

路径由 Codex 从实际任务解析，示例不是让用户照抄。macOS 使用一次性 LaunchAgent：`RunAtLoad=true`、`KeepAlive=false`，没有定时或自动重启，参数逐项传递，不用 shell 拼接。以绝对 Python 虚拟环境入口运行，不解析成失去依赖的系统 Python。规格/日志/启动标记仅保存在用户私人工作区。

`spec.json` 记录工程哈希；`execution.started.json` 独占创建，重复启动立即拒绝；`status.json` 记录 checking/rendering/verifying/encoded/failed。encoded 只说明文件与完整解码完成，**仍待主观验收**。同一 state 不重启；新尝试必须先定位原因并在用户已经允许的次数内显式增加 attempt/max-attempts，不能换目录冒充第一次。后台任务不得因为新会话就再提交一次。

同名输出另有持久 claim，失败时也保留。重试先检查旧进程、状态、暂存文件；在获准次数内使用新 state **及新版本输出名**，例如 `final-v2.mp4`。不要删除 claim 绕过并行/覆盖保护。暂存 MP4 与正式 MP4 用硬链接无覆盖发布，二者不额外复制大文件；导出前实际验证文件系统支持。exFAT 等不支持时，在本地支持硬链接的磁盘完成导出/验收，再复制交付，不在已渲染数小时后才发现无法发布。

检查的原始日志保留诊断文字；程序提取唯一完整 JSON 报告并另存 `check.json`，缺失、损坏或 `ok=false` 都停止。通过 psutil 追踪本次进程及其子进程身份，超时停止已捕获的独立浏览器子进程，先温和退出后有限强停；不会按进程名称关闭用户其他浏览器。它不是对恶意任意派生程序的系统沙箱。

终端/Mac 隐私权限可能首次阻止 Python 访问 Documents/Desktop；查看真实系统提示，由用户允许必要目录，不能关闭系统保护或换路径绕过。任务卡住时先查对应进程、日志更新时间和工作阶段，不凭“文件尚未出现”判失败。

完成后按命令返回的 domain/label 执行 `launchctl bootout <domain>/<label>` 注销任务；仍运行时此命令会停止工作，不能提前调用。不使用 `launchctl submit` 的自动保活默认行为，否则已完成的进程可能被反复拉起；独占标记是第二道防重复保护。

Linux/Windows 可前台运行同一脚本（省略 macOS 参数）。该后台模式只在 macOS 验证，不承诺其他平台系统调度。`HYPERFRAMES_BROWSER_PATH` 可指向用户实际安装的浏览器；不硬编码作者路径。

独立任务完成后，将实际结果接回正常验收链：

```sh
DH record-export <job> --state /path/to/job/export-attempt-1
# 对后期修订另加 --revision <name>
DH verify <job>
# 修订使用 edit-verify；之后按 production.md 记录真实视听，再按需 bundle
```

登记器只接受该任务 exports 中的文件、匹配的 project 哈希、通过的检查和实际视频哈希。重复登记只补证据，不使已有“已交付”状态倒退。不把外部导出成功文字当回执。

## 已定位的问题与相应层级

| 现象 | 先查什么 | 修复与验证 |
|---|---|---|
| 多次导出在聊天切换后消失 | 父进程退出、SIGTERM、活动进程与最后日志阶段 | 换经批准的一次性系统任务；不增加人物生成，不把 detached 环境变量当作抵抗 SIGTERM 的保证 |
| macOS 竖屏底部白边 | 实际编码画面、浏览器原生捕获高度与 captureBeyondViewport | 0.8.48 适配保留 macOS 原生捕获保护；实际短片检查四边，不能只看预览 |
| 长片倒计时/入场被误报迟到 | 固定采样网格是否跨过亚秒入场或一秒数字 | 保留原采样与全部断言，额外采断言截止时点；不删断言、不放松通过门槛 |
| 黑底没有盖住人物/图层闪现 | 定时容器实际尺寸、z-index、透明度初始状态 | 尺寸明确；只由一层拥有时间；在开始前/开始/关键状态/结束后抽查 |
| 横转竖丢失手或脸 | 最终 render 是否落实 object-fit/position；源画幅是否可裁 | 换原生竖屏或本地预裁，保留源与映射；不能假设 CSS 在所有管线都生效 |
| 圆框椭圆/头太小 | 蒙版轴长、整个竖屏源被缩进圆框 | 等轴圆形加独立正方形头部裁切；看转头/手势时范围 |
| 剪映时间边界越界 | 秒到微秒的不同舍入顺序 | 同一整数时间真源，统一转换；不修改原声凑时长 |

`scripts/hf-compat.mjs` 只对固定 0.8.48 的两个精确源码位置做内存适配，不改 node_modules 文件，原文不匹配立即报错。Node 需 22.15+。依赖变动要检查是否仍需适配，不能默默忽略。它解决捕获/采样问题，不改善云端人脸表演。

## 最终文件验收

记录实际 MP4 的编码、原生画幅、fps、总时长、SHA256；完整解码并检查帧时间连续性、音轨长度、混音峰值/响度和意外黑帧/白边。不能用“放大到 4K”宣称人物原生细节为 4K。

关键抽查不是均匀六帧：覆盖每个插片入点/出点、每个复杂效果状态、倒计时各数字、圆框切换、字幕最长句、换声段、最后一句及最后一帧。用一套小联系表查一致性，疑点回到单帧/连续视频。看实际导出，不只看工程截图。

音轨可与已认可源做开头/中间/结尾及剪口的相关性和偏移比较；圆框可比较对应源帧。它们不能证明逐音素口型、眨眼与表情的自然度。分别记录技术通过、视觉/声音实际检查方法、用户认可和仍未验收部分。没有能力播放时如实写明，复用已认可源的证据并只请求确实缺失的检查。

只在全部必要条件通过后交付。输出失败先留日志/状态、核对已有文件，不自动重试、不重新收费。交付后按精确引用与进程检查整理缓存；不删原素材、成功付费结果、状态或必要证据，不重复生成剪映包和 ZIP。
