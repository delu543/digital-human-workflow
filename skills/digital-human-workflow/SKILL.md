# 数字人工作流

工作流版本：0.3.1。全数字人制作；优先保证自然可信，再制作字幕与视听包装。

目标是让用户提供文案与视觉要求，由 Codex 完成编排和执行。默认中文、9:16、1080×1920、约五分钟；以实际音频决定时长。保留原稿观点；不为凑时长静默增加台词。

HeyGen 只负责干净的数字人口播；字幕由实际音频对齐，插片、标题、镜头和混音在独立后期完成。剪映是可选工具，不是必经步骤。用户指定工具时遵从；否则按成片、原生可编辑交付和效果需求选择。训练素材用于创建身份，不擅自把最终出镜方案改为真人实拍。

## 找到工程和私人工作区

1. 如果 Skill 目录有 `installation.json`，只读取它的 `repository` 定位代码；否则解析本 `SKILL.md` 的真实路径，上移两级得到仓库根目录。不要依赖安装者用户名、当前目录或作者绝对路径。
2. 先读仓库 `AGENTS.md`、`INSTALL_FOR_CODEX.md`。代码目录与用户数据目录分别保存；默认建议 `~/DigitalHumanData`，已有用户工作区优先复用。
3. 命令统一使用仓库 `.venv/bin/python -m digital_human --workspace <用户工作区>`；Windows 使用 `.venv/Scripts/python.exe`。以下简称 `DH`。从任何目录执行前将 cwd 设为仓库根目录。
4. 先 `DH doctor`；恢复时只读对应 `jobs/<id>/job.json`、原稿和已存在素材。不得为“继续”重新建付费任务。已完成任务直接返回现有交付。

## 根据状态执行

- 首次安装、缺少账号或声像：读 [初始化](references/onboarding.md)。由 Codex 安装本地依赖、引导最少人工步骤。没有用户声像时只能标记为技术演示。
- 真人感不足、换场景、动作或声音不自然：先读 [真人感检查与基线](references/realism.md) 和 [分层提示词](references/prompts.md)。按原素材→静态形象→配音→短样片→包装逐级排查；用户暂停生成时只做获准的本地/只读工作。
- 已完成初始化、用户提供文案：读 [制作与验收](references/production.md) 和 [独立后期](references/editing.md)。先落实质量计划与可复用模板，试听本次配音，再生成或复用数字人、按真实声学时间制作字幕、编排素材和动画、渲染、验收、打包。中间返回 `needs_quality_plan`、`needs_voice_review`、`needs_edit_plan`、`needs_storyboard` 或 `needs_codex_review` 是 Codex 的下一步，不要让用户手写 JSON。
- 网络中断、余额不足、换计费路径：读 [计费与恢复](references/billing-and-recovery.md)。恢复同一任务；不重复不确定的收费请求。
- 要求剪切、重排、插片、画中画、镜头推近、字幕、音量或剪映工程：读 [独立后期](references/editing.md)，由 Codex 将自然语言改动编成实际计划并执行 edit-build / edit-render / 可选 edit-export。保留原版与已认可声像；不能只返回剪辑建议。旧 storyboard 路径仍可用，复杂 Hyperframes 设计无需被剪映能力限制。

## 权限与质量边界

客户交付、强调真人感或曾否定设计时，读 [制作监制](references/supervision.md)：人物和声音为首要门槛，先验证代表性短片，再铺开全片；集中修正，复用已认可素材，控制返工时间和费用。内容覆盖、画面审美、人物动态与技术检查分别记录，不互相替代。

- 克隆本人或明确获授权的声音/形象。用户完成平台同意与验证；不代替其做身份同意。
- 用户选择 MiniMax 站点和 HeyGen `mcp`、`api` 或 `import` 路径。不得把会员权限当 API 余额，不自动切换账户、区域、声像或账单。
- 密钥只进入用户本地环境变量或 `secrets` 隐藏输入。禁止回显、写入仓库、要求贴到聊天、上传到其他网站。把任务媒体发到供应商之前，要有相同对象、范围、数据去向和预算的授权；已有授权不重复问。
- 对会员 MCP，先查看当前工具说明。若生成工具要求立即 `show_video` 且禁止随后轮询，严格遵守；保存远端 ID 并说明需要用户“继续”或工具通知才能接续。不要借浏览器/HTTP 绕过限制。无人值守能力受所选接口约束。
- 不用字数估算冒充字幕时间，不把技术测试当真人相似度验收，不编造 `review.json` 的通过证据。首次音色/形象须用户验收；后续保持已验收身份并由 Codex 检查成片。
- 新收费视频须通过 `quality-plan` 与绑定音频 SHA256 的 `voice-review`。正式长片复用用户认可的 `baseline_id`；新模板先在有限预算内做短校准。静态场景、声音、动作、剪辑提示词分层，V 默认省略动作提示词，不把作者的个人参数当通用最佳参数。
- 配图由用户授权素材、明确可用的来源、Codex 自制图解或已获授权的图像工具生成；记录来源和权利。人物口型和字幕优先，卡片不要遮住五官。
- 视频插片同样登记来源和权利；先准备有限镜头再决定是否生成。会员/声音授权不自动包含新视频供应商调用；不循环抽样。人物、声音、字幕必须使用同一剪辑映射，不能只剪音频造成口型漂移。
- 可编辑素材包、原生剪映草稿、目标剪映版本已实测是三种状态。原生草稿只有实际打开、改动、保存、冷重开与导出检查后才可称该环境通过。复杂渲染动画内部不可编辑时如实标注，不承诺任意效果无损转换。
- 交付 `final.mp4`、`subtitles.srt` 与 `完整素材包.zip`，报告实际规格、时长和未完成条件。默认不发布到社交平台。
