# v0.6：从数字人口播到广告成片

本版将实际制作中有效的方法整理为可复用的代码和 Codex 执行规范。用户提供文案、必要的授权声像素材与偏好，Codex 负责选材、镜头设计、字幕、混音、核验和交付。它支持广告片，也保留原有知识口播流程；不会把某个客户的身份、语言、服装、画幅或套餐变成所有人的默认值。

## 相比原流程改进在哪里

| 原有基础 | 新增方法与实现 | 对成片的意义 |
|---|---|---|
| 声学字幕、独立 HTML 后期 | 同一组实际语句时间生成双语字幕层、SRT 和抽查点 | 两种语言同时出现，减少漏字、错时、手改不同步 |
| 圆形画中画 | 从多姿态头部边界计算固定方形裁切，再进入圆框 | 避免画布居中却人脸偏左；保留头顶和转头余量 |
| 片段时间映射 | 检查主讲、圆框、预览小窗的可见口型是否都对应当前音源 | 阻止把旧试听或错误 reel 放到正在发声的位置 |
| 图解与线性动画 | 按镜头用途选择实拍、摄影材质、产品展示和编辑式文字 | 避免把无人镜头做成线路图或整页 PPT |
| 插片与混音 | 动作级实拍搜索、分层音乐、音效节制、连续音乐轨 | 内容更贴题，转场和听感更连贯 |
| 长片交付 | 复用已认可成片制作严格限时短版 | 不为混剪再次支付人物或声音费用 |

字幕和动态效果由本地后期完成。HeyGen 负责干净人物；MiniMax 或用户明确认可的声音路线负责最终旁白。画面包装不能替代人物自然度、声音和口型验收。

## 一条清晰的制作顺序

1. **固定需求。** Codex 将原稿、必需镜头、语言、画幅、角色、字幕次序、出镜覆盖、素材限制和预算整理为内部清单。用户已有选择优先，必要信息能读取就不重复问。
2. **先通过声像标准。** 按当前账户核对可用模型和原生规格，绑定真实 look 与声音文件。新声像先短校准，得到认可后再扩展；同标准沿用，不因改字幕重做人物。
3. **建立唯一声音时轴。** 冻结最终旁白及哈希，从实际发音建立语句时间；翻译挂在同一 cue 上。主讲、插片圆框、字幕和 reel 都映射到同一音源坐标。
4. **先做代表性镜头。** 验证一个全屏人物、一个实拍加圆框、一个美术镜头及片头/片尾的设计。先定字体、字号层级、行距、背景对比与运动节奏，再铺全片。
5. **按意义选素材。** 真实活动优先许可实拍；材料、光影、小型图解资产可用 GPT 生图或图生图；连续特殊动作才考虑已授权视频模型。所有路线由需求决定，不要求每片都用 AI 插片。
6. **统一合成与混音。** 各镜头使用同一构图和字幕规范；音乐贯穿段落，语音出现时平滑避让，片头片尾有完整进入与收束。避免每个镜头从头重播音乐。
7. **检查真实文件。** 先检查声明时轴，再核对最终 HTML、实际字幕像素、连续动作与音轨，最后完整解码和文件登记。技术通过不等于真人感已经通过。

## 字幕如何做出美感，同时不漏话

两种语言共享入出点，主次字号、行距和颜色有层次；中文在上或英文在上按用户要求。准确文字独立排版，不让生图模型绘制字幕。长句按语义分组，不能拆英文单词或把一个中文字孤立到下一行。

随背景选择明暗主题；使用有许可的本地字体，检查字体真正加载和字形覆盖。默认字体是可用基线，并非唯一广告字体。字号、行距、留白还要在目标分辨率和手机观看尺寸上检查。字幕短促淡入不推迟开口，动态强调不能占用本应显示口播字幕的时间。

具体规范与数据约定见 [字幕与同步](../skills/digital-human-workflow/references/captions-sync.md)。以下示例供 Codex 调用，不要求用户填写 JSON：

```sh
.venv/bin/python scripts/production_tools.py captions --plan examples/caption-design.json --out .runtime/caption-example
.venv/bin/python scripts/production_tools.py audit --plan examples/production-audit.json --out .runtime/audit-example.json
.venv/bin/python scripts/production_tools.py crop --plan examples/presenter-framing.json --out .runtime/crop-example.json
```

输出不能覆盖已有文件；重做使用新修订目录。字幕生成器输出模板片段，需要放入 `project/compositions/`，由唯一主合成按对应 `composition_id`、起点 0 引入；本地字体路径相对项目根目录，主合成加载本地 GSAP。直接把片段与主文件并列会导致多入口检查失败。完整接线示例是 `scripts/smoke_production.py`。

`audit` 检查的是**声明的计划**，始终返回 `ready_for_delivery: false`：填对 JSON 不能证明画面显示正确、语音自然或逐音素口型准确。`crop` 接收 Codex 从原片多姿态中观察的头部边界，不能自动检测人脸或美化面部。

## 可选项由需求决定

| 用户要求 | Codex 选择与执行 |
|---|---|
| 始终看见数字人 | 提前计算连续出镜/圆框覆盖与费用；旁白发声处使用真实对应口型，静音或其他角色讲话时不放无关张嘴片 |
| 只需部分出镜 | 只生成计划中的人物段，不为未使用的分钟数付费 |
| 真实视频插片 | Pexels、Mixkit 等按可见动作搜索，检查采用段、构图、许可和原文件质量 |
| GPT 生图/图生图 | 优先环境内置工具；先看参考，明确编辑对象与不变项，保存结果并保留文字区；没有需求就不生成 |
| 特殊连续动作 | 检查现有许可素材；确需生成时核实当次工具能力、预算与自然度，不能用推近照片冒充视频 |
| BGM、音效 | 根据品牌情绪选曲、独立铺底及避让；音效服务可见动作，可选择关闭 |
| 横屏/竖屏、单语/双语 | 从源镜头和排版开始设计，避免横片硬裁人物或双语字幕遮住脸 |
| 朋友圈短版 | 选完整表达、减少无意义快切、合理叠化、连续音乐；实际文件严格小于指定时限 |

详细执行入口：[广告导演](../skills/digital-human-workflow/references/advertising.md)、[素材与图像工具](../skills/digital-human-workflow/references/media-art-direction.md)、[声音与音乐](../skills/digital-human-workflow/references/sound-design.md)、[交付变体](../skills/digital-human-workflow/references/delivery-variants.md)。

## 简单使用与真实边界

例如：“把这份文案做成横屏宣传片，英文旁白、中文在上英文在下，真实视频插片，右下圆框，音乐有存在感；沿用已认可形象，费用按我的订阅控制。”用户不必关心中间脚本、字幕 JSON 或编码参数。首次平台验证、必要登录/密钥、声像权利以及新标准的实际试听仍需本人参与；Codex 不代替平台同意。

最高模型、时长、原生分辨率、水印和价格取决于实际账户及当天能力，不写死 Pro/API 或强迫购买某档套餐。已有授权不足时只暂停相关付费步骤。基础 `run` 仍执行确定性流程；高级广告镜头、多 reel 与可选外部工具由 Codex 阅读 Skill 后编排，不是一个命令已经自动接入所有供应商。

公开仓库只保存通用规范、虚构示例和代码。私人基线、声音、参考图、客户文案、日志和令牌留在各自工作区。本次实际测试及尚未验证的范围见 [VALIDATION](VALIDATION.md)。
